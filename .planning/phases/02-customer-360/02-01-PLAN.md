# Plan 02-01: Additive Customer Model & Aggregated Summary Backend API

## Objective
Extend the MongoDB `Customer` schema with additive CRM fields (email, credit limit, payment terms, lifecycle stage, notes) and create the `/api/customers/:id/summary` endpoint providing consolidated financial ledger metrics and quotation history without disrupting existing CRUD operations.

## Context
Currently, `Customer.js` only stores basic address book fields (`name`, `phone`, `gstNumber`, `state`, `address`, `tags`). To support CRM workflows and financial visibility, the backend needs to compute customer lifetime value, outstanding balance, overdue amounts, and transaction history.

## Tasks
1. **Extend Customer Schema (`Customer.js`)**:
   - Add optional additive fields with safe defaults:
     - `email`: String (default: '')
     - `creditLimit`: Number (default: 0)
     - `paymentTermsDays`: Number (default: 30)
     - `lifecycleStage`: String (enum: `['Lead', 'Prospect', 'Active', 'Dormant']`, default: 'Active')
     - `notes`: String (default: '')
   - Enable Mongoose timestamps (`{ timestamps: true }`).
2. **Implement `/api/customers/:id/summary` Endpoint (`customerRoutes.js`)**:
   - Query customer record by ID.
   - Aggregate all related invoices by `customerId` and fallback to `customerPhone`.
   - Aggregate all related quotations by `customerId` and fallback to `customerPhone`.
   - Compute financial summary:
     - `totalInvoiced`: Sum of all invoice totals.
     - `totalPaid`: Sum of all payments received (`paidAmount`).
     - `balanceDue`: Outstanding balance across all invoices (`totalInvoiced - totalPaid`).
     - `overdueBalance`: Sum of balances for invoices past their due dates.
     - `quotationsCount`: Total quotations issued.
     - `convertedQuotationsCount`: Number of quotations successfully converted to invoices.
     - `conversionRate`: Conversion percentage.
   - Return `{ customer, summary, invoices, quotations }`.

## Acceptance Criteria
- [ ] Existing `POST /api/customers`, `GET /api/customers`, `PUT /api/customers/:id` continue to function identically.
- [ ] `GET /api/customers/:id/summary` returns accurate aggregated ledger metrics.
- [ ] Existing documents without new fields remain valid with safe defaults.
