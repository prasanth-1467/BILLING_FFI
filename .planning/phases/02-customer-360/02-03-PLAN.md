# Plan 02-03: End-to-End Ledger Verification & Production Build Validation

## Objective
Verify the Customer 360 view, validate that backend aggregation matches underlying invoice and quotation database records, test edge cases (customers with 0 invoices, customers with partial payments, customers without GSTIN), and verify production build.

## Context
Phase 2 introduces additive database fields and a dedicated ledger aggregation endpoint. This plan ensures strict data integrity, zero regression to existing billing operations, and smooth frontend interactions.

## Tasks
1. **Frontend Production Build**:
   - Run `npm run build` in `billing-frontend` to confirm clean compilation with zero bundling errors.
   - Run ESLint to ensure strict code quality.
2. **Backend Aggregation Verification**:
   - Verify `/api/customers/:id/summary` returns correct mathematical sums: `totalInvoiced - totalPaid === balanceDue`.
   - Verify behavior for customers with zero transactions (empty array, zero totals, no division-by-zero on conversion rate).
3. **Core Workflows Sanity Check**:
   - Confirm creating a new invoice or quotation automatically reflects in the customer's 360 transaction ledger.
   - Confirm invoice PDF generation remains intact.
   - Confirm quotation conversion flow is unaffected.
4. **Log Verification**:
   - Document results in `.planning/phases/02-customer-360/VERIFICATION.md`.

## Acceptance Criteria
- [ ] `npm run build` exits with code 0.
- [ ] Ledger aggregations match invoice balances accurately.
- [ ] Zero breaking changes to existing billing, GST calculations, or PDF generation.
