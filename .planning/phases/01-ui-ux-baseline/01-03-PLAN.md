# Plan 01-03: Responsive Viewport Verification & Production Build Validation

## Objective
Verify the updated UI/UX across desktop and mobile viewports, confirm zero regressions across all core workflows (Invoicing, Quotation conversion, POs, PDFs), and validate that the production build succeeds without warnings or syntax errors.

## Context
Phase 1 focuses entirely on UI/UX modernization without altering backend APIs or core calculations. This verification plan ensures the application meets high usability standards across all device sizes and passes production bundling.

## Tasks
1. **Production Build & Type/Syntax Verification**:
   - Run `npm run build` in `billing-frontend` to confirm clean compilation and asset bundling.
   - Verify ESLint checks pass (`npm run lint` or equivalent).
2. **Multi-Viewport Visual Inspection**:
   - Inspect Desktop layout (1440px / 1280px): sidebar fixed, content centered with max-w container, sticky header aligned.
   - Inspect Mobile layout (375px / 425px): hamburger opens drawer, menu clicks route properly, table overflow handles scrolling without breaking layout.
3. **Core Workflows Sanity Check**:
   - Verify PDF export buttons on Invoices and Quotations continue to function.
   - Verify Customer search and filter tabs continue to function.
   - Verify Notification bell dropdown opens and displays notifications.

## Acceptance Criteria
- [ ] `npm run build` exits with code 0 in `billing-frontend`.
- [ ] Mobile drawer navigation functions without visual defects.
- [ ] Zero changes to backend APIs, database models, or PDF generation logic.
- [ ] Summary report logged to `.planning/phases/01-ui-ux-baseline/VERIFICATION.md`.
