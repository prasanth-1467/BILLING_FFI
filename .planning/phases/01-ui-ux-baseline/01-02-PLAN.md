# Plan 01-02: Standardized UI Primitives & Viewport Consistency

## Objective
Introduce reusable, production-grade UI primitives (`PageHeader`, `TableSkeleton`, `EmptyState`, `StatusBadge`) and integrate them into primary data tables (`Invoices`, `Quotations`, `Customers`, `Products`) to eliminate jarring raw spinners and inconsistent table headers.

## Context
Currently, each listing page independently implements title headers, inline spinners (`<Loader className="animate-spin" />`), and bare text messages when zero records are returned. Standardizing these into composable UI primitives drastically elevates the software's visual polish and perceived performance.

## Tasks
1. **Create Composable UI Primitives** in `billing-frontend/src/components/common/`:
   - `PageHeader.jsx`: Title, subtitle, stats/badge, and responsive action button slots.
   - `TableSkeleton.jsx`: Pulsing skeleton table with customizable row/column counts.
   - `EmptyState.jsx`: Centered modern illustration/icon, title, message, and CTA button.
   - `StatusBadge.jsx`: Standardized colored pills for financial statuses (Paid: green, Pending: yellow, Overdue: red, Draft: slate, Converted: indigo).
2. **Integrate Primitives in List Views**:
   - `Invoices.jsx`: Replace custom header and spinner with `PageHeader` and `TableSkeleton`; use `EmptyState` when filter yields 0 invoices; use `StatusBadge` for invoice payment status.
   - `Quotations.jsx`: Standardize header, loading state, and quote status badges.
   - `Customers.jsx`: Standardize header, category tag badges, and empty search results.
   - `Products.jsx`: Standardize stock alert badges, header, and skeleton.

## Acceptance Criteria
- [ ] List views render pulsing table skeletons during data fetching instead of full-page raw spinner.
- [ ] Empty state renders friendly CTA when no data matches active filter or search term.
- [ ] Status badges follow consistent semantic color codes across all tables.
- [ ] All table search, pagination, filter, and action buttons remain 100% operational.
