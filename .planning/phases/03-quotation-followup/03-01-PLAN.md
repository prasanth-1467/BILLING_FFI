# Plan 03-01: Additive Quotation Follow-up Schema & Backend API

## Objective
Extend `Quotation` schema with non-breaking follow-up fields (`followUpDate`, `followUpNotes`, `followUpStatus`) and provide a lightweight `PATCH /api/quotations/:id/follow-up` endpoint for immediate follow-up updates without revalidating entire quotation items.

## Context
Currently, `Quotation.js` only tracks `status` (Draft, Sent, Approved, Converted, Rejected) and general quotation data. Sales staff have no way to record when they scheduled a follow-up call, client objections, or negotiation notes.

## Tasks
1. **Extend Quotation Schema (`Quotation.js`)**:
   - Add fields with safe defaults:
     - `followUpDate`: Date (default: null)
     - `followUpNotes`: String (default: '')
     - `followUpStatus`: String (enum: `['Pending', 'Contacted', 'Awaiting Approval', 'Negotiation', 'Won', 'Lost']`, default: 'Pending')
2. **Implement Follow-up Endpoint (`quotationRoutes.js`)**:
   - Add `PATCH /:id/follow-up` route:
     - Accepts `{ followUpDate, followUpNotes, followUpStatus }`.
     - Updates and returns the quotation document.
     - Does not alter pricing, taxes, or PDF layout.

## Acceptance Criteria
- [ ] `PATCH /api/quotations/:id/follow-up` successfully updates follow-up fields.
- [ ] Existing quotation creation, update, PDF generation, and deletion endpoints remain 100% operational.
- [ ] Existing quotations in database without these fields remain valid with null/default values.
