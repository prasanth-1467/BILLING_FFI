# Research: Architectural Blueprint & Compatibility Strategy

## 1. Compatibility Principles
- **Schema Extensibility**: Additive fields only to MongoDB schemas. Existing schemas (`Customer`, `Invoice`, `Quotation`, `PurchaseOrder`) must remain backward-compatible with existing documents and queries.
- **API Stability**: Do not modify existing API route signatures (`/api/customers`, `/api/invoices`, `/api/quotations`, `/api/stats`). Extend payloads with optional fields or provide dedicated sub-routes (e.g., `/api/customers/:id/summary` or `/api/customers/:id/interactions`).
- **PDF Generation Invariant**: `utils/pdf/` and inline PDFKit streams in `invoiceRoutes.js` and `quotationRoutes.js` expect specific shape structures. Any additions to invoice/quotation state must not alter the numeric precision or layout parameters.

## 2. Customer Schema Expansion
The existing customer model in `billing-system/models/Customer.js`:
```js
{
  name: String,
  phone: String,
  gstNumber: String,
  state: String,
  address: String,
  tags: [{ type: String }] // "Farmer", "Dealer", "Contractor", "Institution"
}
```
Non-breaking additions:
- `email`: String (optional)
- `creditLimit`: Number (default: 0)
- `paymentTermsDays`: Number (default: 30)
- `lifecycleStage`: String (enum: `['Lead', 'Prospect', 'Active', 'Dormant']`, default: `'Active'`)
- `notes`: String
- `interactions`: `[{ date: Date, type: String, summary: String, nextFollowUp: Date, createdBy: ObjectId }]`

## 3. CRM Dashboard Aggregation Architecture
The current dashboard calls `/api/invoices` and `/api/customers` directly and computes metrics client-side.
- **Problem**: Client-side full-scan aggregation becomes sluggish as invoice history grows.
- **Solution**: Enhance `/api/stats` or introduce optimized backend aggregations for:
  - Total Receivables & Aging Buckets (0-30 days, 31-60 days, 60-90 days, 90+ days overdue)
  - Quotation Pipeline Funnel (Draft -> Sent -> Approved -> Converted to Invoice)
  - High-Value / Top Receivable Customers
  - Feed from `Notification` collection generated by background agents

## 4. Background Agent Integration
The existing `billing-system/agents/`:
- `InsightAgent`: Already generates daily revenue and overdue payment notifications. Can be enhanced to flag aging accounts and high-value quotation follow-ups.
- `InvoicerAgent`: Suggests converting quotations created within 7 days. Can be tied directly into the CRM pipeline.
- `RestockAgent`: Monitors inventory thresholds.
